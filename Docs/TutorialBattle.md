# TutorialDemo 전투·몬스터 연결

## 실행과 조작

### 선제 진입 추가 행동 (2026-09-19)

- 플레이어 선제 진입은 플레이어에게, 몬스터 접촉 진입은 접촉한 몬스터 한 기에게 일반 턴보다 먼저 1회 행동 기회를 준다. 기존 충돌 메모리 +1도 함께 적용한다.
- 추가 행동은 1라운드 기본 행동권을 소모하지 않는다. 이후 남은 메모리로 일반 순서를 다시 계산한다. 메모리가 변하지 않는 1:1 예: 플레이어 선제/빠름 `플→플→적→플`, 플레이어 선제/느림 `플→적→플`, 몬스터 선제/플레이어 빠름 `적→플→적`, 몬스터 선제/몬스터 빠름 `적→적→플`.
- 기본 상태이상 판정은 추가 행동에도 적용한다. 행동 불능이면 선제 기회만 소모하고 기본 행동권은 남긴다. 선제 공격으로 전투가 끝나면 후속 행동은 실행하지 않는다.
- `BattleSession.Start(participants, entryCondition, initiatorId)`의 선택 인자로 실제 진입 개체 ID를 전달한다. 생략한 기존 호출은 해당 팀의 첫 생존 개체를 사용한다. TutorialDemo는 플레이어 ID 또는 접촉한 몬스터 ID를 명시한다.
- 필드에서는 가까운 몬스터에 마우스 좌클릭으로 선제 진입한다(거리 2.5m 이내, 시야 확보). 커서가 잠긴 필드 조작 중에만 작동하며, 근접 접촉 진입은 유지한다. 실제 필드 공격 판정은 같은 `BeginBattle`에 연결할 수 있다.
- 검증: Unity 컴파일 설정으로 코어·테스트·Assembly-CSharp 컴파일 성공. 코어 테스트 160개를 에디터 외부에서 직접 실행해 모두 통과(선제 4순서, 접촉 개체 지정, 투자 후 재정렬, 행동 불능, 잘못된 개체 검증 포함). MCP 연결 불가로 에디터 실행 검증은 수행하지 않았으며 데모/PlayMode도 실행하지 않았다.

### 공통 플레이어 상태와 공격 연출 (2026-09-18)

**기획 답변 반영:** 비전투 필드 진입/복귀 시 메모리는 DT 최초값으로 자동 회복한다. HP 자동 회복은 새로 추가하지 않는다. 폭주·각인·메모리 고갈·행동 불능 등 상태이상은 전투 종료 시 필드/다음 전투로 전달하지 않는다. 충돌 진입 보너스는 몬스터마다 추가 메모리 1이며 `Tutorial Battle > Collision Memory Bonus`에서 밸런싱한다(컴포넌트 기본값·TutorialDemo 저장값 모두 1).

- `PlayerSessionState.Current`의 `PlayerRuntimeState`가 플레이 세션의 HP·메모리를 보관한다. 같은 캐릭터로 씬을 다시 초기화해도 값을 덮어쓰지 않는다. PlayMode를 새로 시작하면 초기화하며 디스크 저장 기능은 포함하지 않는다.
- 전투 시작은 공통 상태의 HP·메모리를 읽고, 행동/턴 결과 갱신 시 전투 스냅샷을 공통 상태에 반영한다. 필드 HP 바와 HP·메모리 문구는 `Changed` 이벤트로 갱신된다. 승리 후 HP는 유지하며 메모리는 최초값으로 회복한다. 패배/무승부에서는 기존 정책대로 최대 HP·초기 메모리로 복구한다.
- 필드 아이템 등에서 값을 변경할 때는 `PlayerSessionState.Current.SetVitals(hp, memory)`를 사용한다. 전투 중 계산은 `BattleSession`에서 수행하고 결과를 반영한다. 폭주·연쇄·각인은 전투별 상태로 유지한다.
- 몬스터도 플레이어와 동일하게 접근 → 타격 → 복귀한다. 공격하는 몬스터만 움직이며 대상이 피해를 입었을 때만 색상·위치 반응을 표시한다. 빗나감은 접근/복귀만, 방어·행동 불능은 이동하지 않는다. 중단 시 위치·공격 전 회전·머티리얼 속성을 복구한다.
- 플레이어 피격 시 공격에 따른 카메라 이동 및 줌은 적용하지 않는다. 평상시의 느린 카메라 움직임과 우클릭 회전은 유지한다.
- 검증: Unity가 생성한 Assembly-CSharp 컴파일 응답 파일과 동일한 참조/정의로 최신 스크립트 컴파일 성공(기존 UnityChan 중복 타입 경고만 존재). Unity에서 컴파일된 코어/테스트 DLL의 신규 상태 테스트 2개를 에디터 외부에서 직접 실행해 통과했다. MCP 세션 연결 대기 상태로 이번 변경의 에디터 UI·연출 검증은 아직 수행하지 않았다. PlayMode/데모는 실행하지 않았다.

`Assets/CK_Semester_Project/Prototype/Scenes/TutorialDemo.unity`를 열어 사용한다.
기존 UnityChan 캐릭터, 카메라, 배경과 필드 UI를 유지했다. 몬스터는 각인·잔상·망각 회색 Cube 3종이며 새 아트는 만들지 않았다.

- WASD: 이동. 이동 시 간격을 두고 발소리 이벤트를 보낸다.
- Space: 반경 12m 소리 이벤트. 오디오 재생은 연결하지 않았다.
- 근거리 E: 가장 가까운 몬스터와 선제 진입. 벽으로 가려지면 진입하지 않는다.
- 몬스터와 근접: 접촉 진입. 전투 진입 시 플레이어 이동, 필드 카메라 입력, 모든 몬스터 FSM을 멈춘다.
- 전투: 대상 버튼 또는 숫자 1~3으로 대상 선택 → 투자 0~5단계 선택 → 잔상/각인/망각 버튼으로 스킬 실행. 방어 버튼은 같은 투자 단계를 사용한다.
- 적 행동은 공통 MonsterAi로 선택하고, 결과 표시 시간 뒤 다음 행동으로 진행한다. 플레이어는 선택한 대상에게 접근·복귀하고 대상은 피격 시 흔들림·색상 반응을 표시한다.
- 결과 확인: 승리한 몬스터는 비활성화하고 HP는 보존하며 메모리를 최초값으로 회복한다. 패배/무승부는 시작 위치와 HP·메모리를 복구한다. 다른 몬스터는 탐색을 재개한다. 재진입 유예는 3초다.

## 구성

- `Tutorial Battle/TutorialBattleController`: 필드→전투→필드 전환과 독립 전투 패널 연결.
- 각인/잔상/망각 몬스터: NavMeshAgent + 기존 EnemyStateMachine. 배회·독립 시각/청각·추적·탐색을 사용한다.
- `Tutorial Navigation`: 기존 바닥·벽과 NavMeshSurface. `Prototype/Data/TutorialNavMesh.asset`에 베이크 결과를 저장했다. 지형 변경 시 재베이크해야 한다.
- `Canvas/BattleUI`: 원본 필드 UI다. 버튼 문구·폰트·이미지·배치·이벤트를 유지한다. HP 바는 공통 플레이어 상태에 연결하며 HP·메모리 수치 문구를 바 위에 추가한다.
- `Encounter Canvas/Encounter UI`: 별도 전투 조작 패널. 필드 UI의 그림을 사용하지 않고 기본 버튼·상태 문구를 사용한다. 탐색 중 숨기고 전투 중에만 표시한다. 전투 종료 후 필드 UI의 이전 표시 상태를 복구한다.
- `Character_DT`의 CH00과 `Skill_DT.csv`를 읽는다. 잘못된 데이터는 로그를 남기고 전투 연결을 비활성화한다. 기본 BattleRules의 명중·속성·연쇄·폭주·행동 불능·메모리 고갈을 사용한다.

몬스터 DT 수치가 없어 HP 600, 메모리 100, 공격 90, 각인 속성 및 4단계 연쇄는 연결 검증용 임시 설정이다. HP·메모리와 접촉 추가 메모리는 Inspector에서 바꿀 수 있다. 접촉 보너스는 확정 수치가 없어 기본 0이다.

## 필드 UI 원복 확인

원본 필드 UI에 해당하는 Unity 직렬화 레코드 56개를 병합 직후 HEAD와 동일하게 복원했다. 전투 패널의 객체 ID와 참조는 별개로 분리했으며 새로 끊긴 로컬 참조가 없는지 검사했다. 이 원복 시점에는 MCP 연결이 거절되어 Unity 화면·컴파일 재검증은 하지 못했다. 위 108개 통과는 원복 이전 코어 검증 기록이다.


## 전투 자리 배치

전투 진입 시 접촉 위치 근처에서 양측이 기본 9m 떨어져 서로 마주 본다. `Tutorial Battle`의 `Battle Spacing`에서 간격을 조절한다. 전투 중에는 CharacterController와 해당 몬스터의 NavMeshAgent를 비활성화해 밀림·자동 회전 없이 각자의 자리를 유지한다.

자리 후보는 현재 대치 방향부터 좌우로 회전하며 찾는다. 같은 NavMesh에서 도달 가능한 바닥, 두 자리 사이 시야, 벽·다른 몬스터와의 겹침을 확인한다. 안전한 자리가 없으면 상태를 바꾸지 않고 전투 진입을 거절한다.

승리 시 플레이어를 전투 직전 필드 위치·방향으로 복구하고 처치한 몬스터는 비활성화한다. 패배/무승부 시 플레이어는 기존 규칙대로 시작 위치로 돌아가고 몬스터는 전투 전 자리로 돌아간다. 전투 제어 컴포넌트가 중간에 비활성화된 경우도 원래 자리를 복구한다. 필드 UI, 박스 모양, 배경 아트는 변경하지 않았다.

이번 검증: Unity 컴파일 오류 없음. 두 몬스터 각각에 대해 4m 간격·서로 마주 보기·이동 제어 잠금·중복 배치 거절·위치와 회전 및 제어기 활성 상태 복구·복구 재호출·배치 불가능 공간 거절을 편집 모드에서 확인했다. PlayMode는 실행하지 않았다.


## 레퍼런스 구도 반영

전투 카메라는 플레이어 오른쪽 어깨 뒤에서 낮게 바라본다. 기본 로컬 오프셋은 (오른쪽 2.2m, 높이 1.3m, 뒤쪽 2.3m), 수직 시야각 56도다. 플레이어가 왼쪽 전경에 크게, 몬스터가 오른쪽 중경에 작게 들어오도록 목표 지점을 정한다. `Battle Camera Offset`과 `Battle Field Of View`에서 조절할 수 있다.

벽에 가리는 카메라 자리는 사용하지 않는다. 높이를 조금 조절해도 보이지 않으면 전투 자리 후보의 대치 방향을 바꾼다. 플레이어 발·머리와 몬스터가 화면 안에 들어오는지도 확인한다. 전투 종료 시 원래 카메라 위치·회전·시야각·투영 방식을 복구한다.

기존 UI와 박스 몬스터, 배경 자산은 그대로다. 두 몬스터 × 16:9/4:3/21:9 비율의 배치·카메라 후보를 편집 모드에서 검사했다. 정지 화면 캡처로 왼쪽 전경/오른쪽 중경 구도를 확인했다. PlayMode를 실행한 검증은 아니다.


## 와이드 구도와 동적 카메라

전투 진입 시 검증된 전투 구도로 전환한 뒤, 0.85초 동안 뒤쪽 0.65m·위쪽 0.2m에서 기본 자리로 접근한다. 이 동안 행동 선택과 자동 턴 진행을 잠근다. 대기 중에는 좌우 0.18m의 느린 이동을 적용한다. 스킬 행동 중에는 공격 주체에 따라 좌우 진행 방향을 바꾸고 최대 0.45m 전진하며 시야각을 최대 2도 좁힌다. 행동 불능과 방어에는 공격 이동을 적용하지 않는다. 위치·회전·시야각은 프레임 시간에 맞춰 부드럽게 보간한다.

벽과 참가자 가림, 화면 내 배치를 검사한 후보만 사용하며 이동 구간도 반경 0.2m 구체로 검사한다. 시작 구도가 막히면 기본 구도에서 시작하고, 동작 후보가 막히면 기본 구도로 복귀를 시도한다. 필드 카메라 복구 규칙은 유지한다.

검증: 현재 활성 Monster Box 1에서 16:9·4:3·21:9 각각 양쪽 공격 방향 42개 표본의 배치와 카메라 이동 경로가 통과했다. Unity 컴파일 오류 0건. 정지 렌더 `Logs/battle-wide-preview.png`로 넓어진 구도를 확인했다. PlayMode는 실행하지 않았으므로 실제 시간 흐름의 체감은 아직 확인하지 않았다. 정지 렌더에는 전투 UI와 런타임 애니메이션이 포함되지 않는다.


전투 간격 조정: 기본 간격을 4m에서 7m로 늘렸다. 카메라 거리 보정은 간격 비율의 제곱근으로 완화해, 간격을 늘린 만큼 전장 여백과 원근 차이가 보이도록 했다.


전투 진입 예외 수정: 몬스터 배열의 Missing/None 항목 접근으로 발생한 NullReferenceException을 수정했다. FSM 일시 정지·복구에서 삭제/미연결 항목을 건너뛰고, 전투 종료 후 잔여 몬스터 판정도 null을 제외한다. 편집 모드에서 정상 참조 + null + 삭제된 Unity 객체를 섞어 정지/복구와 기존 비활성 상태 유지가 통과했다. 컴파일 오류 없음. PlayMode 전투 재현은 실행하지 않았다.


## 마우스 회전과 반복 작업 감소

전투 간격은 기본 9m다. 우클릭을 누른 채 마우스를 움직이면 전장 중심을 기준으로 좌우·상하 회전한다. 첫 드래그 프레임의 커서 잠금 델타를 무시하며, 버튼을 놓거나 포커스를 잃으면 커서를 돌려준다. 회전 각도는 유지하고 기존의 작은 자동 움직임을 함께 적용한다. 벽·시야·화면 범위를 벗어나는 후보는 거절한다. 전투 진입 카메라 이동 중에는 드래그를 받지 않는다. 탐색 복귀 시 기존 필드 카메라로 돌아간다.

전투 스냅샷을 상태 변경 시에만 새로 만들고 UI 역시 진입 완료·행동 결과·투자 변경·다음 행동 전환 시 갱신한다. 필드의 최근접 몬스터 검색은 매 프레임 정렬 대신 단일 순회로 처리한다. 카메라의 물리 조회는 고정 버퍼를 재사용하며 버퍼가 가득 찬 경우 안전하게 후보를 거절한다.

DT 전체 검색은 에디터 세션 첫 검사와 변환기 코드 변경 시 수행하고, 일반 Play 도메인 재로드에서는 반복하지 않는다. XLSX 파일 변경과 명시적 전체 재임포트·빌드 검증은 유지한다.

검증: Monster Box 1에서 세 화면 비율 모두 실제 간격 9m 배치·복구 성공. 각 비율의 회전 표본 15개 중 9개 허용, 6개는 안전 조건으로 거절. 카메라 배치/회전/경로 조회 100회에서 관리 힙 할당 0바이트 확인. 컴파일 오류 0건. UnityChan 중복 타입 경고는 남아 있다. PlayMode를 실행하지 않아 실제 시작 지연의 원인과 개선 시간, 마우스 입력 체감은 아직 실측하지 않았다.


카메라 근접 조정: 플레이어와 적의 9m 간격은 유지하고 기본 카메라 오프셋을 (2.2, 1.3, -2.3)으로 줄였다. 9m 대치 기준 플레이어에서 카메라까지 약 7.46m → 5.16m로 가까워진다. 세 화면 비율의 배치와 기본 회전 후보, 컴파일 오류 없음 및 정지 렌더를 확인했다. PlayMode는 실행하지 않았다.


## 임시 접근 공격과 몬스터 피격

플레이어가 몬스터를 대상으로 스킬을 사용하면 1.2초 동안 접근(35%) → 타격 유지(20%) → 복귀(45%)를 수행한다. 기본 9m 대치에서 적 앞 1.6m까지 약 7.4m 이동한다. 이동 경로에 다른 장애물이 있으면 돌진 이동은 생략한다. 명중했고 실제 몬스터 HP 감소가 있을 때 타격 시점에 붉은 플래시·짧은 흔들림·작은 밀림을 적용한다. 빗나감은 접근/복귀만 수행하고 방어·행동 불능·턴 시작 효과에는 접근하지 않는다.

공유 머티리얼 에셋은 수정하지 않으며 MaterialPropertyBlock의 원래 값을 복구한다. 연출 완료·중단·필드 복귀 모두 전투 자리와 피격 색상을 복원한다. 카메라는 캐릭터의 순간 이동 위치가 아닌 원래 전투 자리로 구도를 계산한다. 전투 로직의 HP 계산 시점은 그대로이고, 다음 행동 진행은 복귀 완료 이후다. 몬스터의 공격 접근과 정식 공격 애니메이션은 이번 임시 연출에 포함하지 않았다.

편집 모드에서 실제 BattleSession 결과로 명중/빗나감/방어를 검사했다. 명중 시 7.4m 접근·플래시·흔들림, 빗나감 시 피격 효과 없음, 방어 시 이동 없음, 완료 및 중단 시 복귀·복구 재호출, 연출 대기 단계 유지가 통과했다. Unity 컴파일 오류 없음. PlayMode는 실행하지 않았다.


## 속성별 몬스터 AI 추가

현재 TutorialDemo에는 각인·잔상·망각 몬스터 박스 3종이 있다. 각 `TutorialMonster` 컴포넌트에 연결된 `Data/Monsters` 정의 에셋을 사용한다. 기획서 기반 단독 AI 및 코어의 2기 조합 규칙, Inspector 편집 항목과 미확정 해석은 `Docs/MonsterAI.md`를 참조한다. 씬 전투는 아래 1~3기 설정을 사용한다. 기존 임시 fallback 몬스터는 정의 컴포넌트가 없는 경우에만 사용한다.


전투 배경 몬스터 숨김: 참가하지 않은 등록 필드 몬스터는 전투 중 GameObject를 비활성화한다. 복귀/중단 시 저장한 activeSelf를 복원하며, 이미 비활성인 몬스터를 다시 살리지 않는다. FSM 복구 전에 표시 상태를 복원한다.

## 1~3기 전투 설정

- `Tutorial Battle` → `TutorialBattleController` → `Encounter Size`: 1~3. TutorialDemo 저장값은 3, 컴포넌트 기본값은 1이다.
- 접촉 몬스터 + 가까운 살아 있는 등록 몬스터 순서로 구성한다. 중복 참조는 제외하며 부족한 수만큼 생성하지 않는다. 각 개체는 별도 전투 ID를 가진다.
- 플레이어와 적 진형 중심 사이 9m, 몬스터 간 목표 간격 2.5m. NavMesh·장애물·카메라에 들어오는지 검사하고 실패하면 진입을 취소한다.
- 3기 배치에서 대상 1은 중앙, 2는 왼쪽, 3은 오른쪽이다(플레이어가 적을 바라보는 방향 기준). 2기 배치에서는 1이 왼쪽, 2가 오른쪽이다.
- 대상별 HP·메모리·폭주·연쇄와 이름 옆 속성을 표시한다. 대상 버튼/숫자 1~3으로 선택하며 사망한 대상은 제외하고 살아 있는 첫 대상으로 자동 전환한다.
- 사망 연출 시간이 끝나면 해당 박스를 숨긴다. 전원을 처치해야 승리하며, 승리 후 참가 몬스터 전체를 비활성화한다. 패배/중단 시 참가자 위치와 활성 상태를 복구한다. 비참가자는 원래 활성 상태를 유지한다.
- 3기 AI는 단독표 임시 적용, 생존 2기부터 기존 조합표 적용. 랜덤 출현 확률과 별도 증원 생성은 아직 정의하지 않았다.

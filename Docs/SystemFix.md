# 2026-09-23 시스템 수정

기준: `References/시스템 픽스 문서.docx` 및 사용자의 잔상 순소모 10 확정 답변.

## 적용

- 선제 추가 행동을 받는 1:1 잔상은 공격 후 두 번째 행동에 기존 방어를 사용한다. 일반 진입과 2기 조합표는 유지한다. `BattleSession.EntryInitiatorId`로 실제 추가 행동 수혜자를 구분한다.
- 폭주는 플레이어 전용이다. 공통 상태 생성 시 몬스터 폭주·과열을 제거하고, 몬스터 스킬 폭주 획득 및 정의 에셋의 획득량 필드를 제거한다. 몬스터 상태 UI에서도 폭주를 표시하지 않는다.
- 모든 AI의 방어 분기(잔상 첫 방어, 망각 조건 방어, 비용 부족 시 방어)는 플레이어 과열 상태에서 금지한다. 공격 비용이 부족하면 대기로 진행한다. 플레이어가 폭주 행동 불능을 소모한 이후에는 기존 AI 조건을 다시 적용한다.
- SK00 기본 비용 10→13. 잔상 명중 회복 3을 유지하므로 순소모 7→10. 빗나감은 회복 없이 13 소모한다. 투자 비용은 별도이며 시전에는 기본 비용 13 이상이 필요하다.

## 미확정

약점 연쇄 순서: 원문이 ‘회의 필요’로 명시했으므로 기존 데이터를 유지한다.

## 검증

Unity 컴파일러로 CK.Battle.Core, CK.Battle.Core.Tests, Assembly-CSharp 컴파일 성공. 에디터 외부에서 기존 및 회귀 테스트 169개 통과. 선제 잔상 공격→방어, 3속성 및 일반 AI의 과열 시 방어 금지, 몬스터 폭주 무효화, 잔상 명중·빗나감 순소모를 포함한다.

이번 세션에는 Unity MCP 도구가 제공되지 않아 에디터 Console 및 PlayMode 실행은 확인하지 않았다.

# 2026-10-04 시스템 수정

기준: `References/시스템 픽스 문서.pdf`의 10-04 항목. 몬스터 방어 추가 조건은 초기 요청에서 보류했으며, 아래의 사용자 확정 조건을 추가 적용했다.

## 적용

- MonsterAI_Test의 9기와 TutorialDemo의 3기는 각인 빨강, 잔상 파랑, 망각 보라의 단색 박스로 구분한다.
- 망각은 명중 시 최대 5 강탈한다. 대상의 남은 메모리와 행동자의 최대 메모리 여유 범위에서 동일한 양을 이동한다. 스킬/투자 비용은 먼저 소모한다.
- 각인은 최종 스킬 피해의 10%를 대상의 다음 행동 시작에 한 번 적용한다. 플레이어와 몬스터 모두 동일하며, 피해와 다음 행동 재개를 기록에서 확인할 수 있다.
- 잔상은 명중 후 바로 다음 자신의 행동이 방어면 메모리 10을 한 번 회복한다. 다른 행동이나 행동 불능이면 사라지며, 다른 개체의 행동에는 소모되지 않는다. 최대 메모리까지만 회복한다. 문서의 다음 턴 조건을 다음 자신의 행동 기회로 해석했다.
- 즉시 회복 3이 없어져 SK00 기본 소모를 13에서 10으로 조정했다. 명중/빗나감 모두 기본 10, 투자 비용은 별도다.
- MonsterAI_Test 오른쪽 위 `전투 기록` 버튼으로 전체 기록을 열고 휠로 스크롤한다. 사용 스킬/방어/대기, 메모리 사용량, 투자 단계, 명중/치명타, 피해, 방어로 줄인 피해, HP·메모리 전후 값, 각인 피해, 승패를 표시한다. 전투 종료·필드 복귀 후에도 유지하며 다음 전투 시작 시 새 기록으로 전환한다.
- 공개 읽기 API: `BattleSession.History`, `TutorialBattleController.History`, `CombatantState.HasAfterimageRecovery`. 기존 직렬화 필드 이름은 변경하지 않았다.

## 검증

Unity 6000.3.23f1 컴파일러로 코어·테스트·게임 스크립트를 컴파일하고 에디터 외부에서 코어 회귀 테스트를 실행했다. PlayMode/데모 실행은 하지 않았다. 현재 Unity MCP에는 다른 프로젝트만 연결되어 이 프로젝트의 Console 및 실제 화면 검증은 하지 못했다.

## 새 통합 문서 방어 확인

`References/전투 시스템 통합 문서 (2).pdf` 8쪽의 방어 규칙은 현재 구현과 일치한다. 플레이어 피해 50% 감소, 투자 단계별 폭주 감소 10·15·20·25·30을 유지한다. 방어는 다음 자신의 행동 시작까지 적용한다. 몬스터 AI 문서에서 지정한 잔상 추가 피해 감소도 유지한다. 첨부 파일에는 새 몬스터 방어 추가 조건이 기재되어 있지 않다.

몬스터 3기의 투자·치명타 공격에 모두 50% 감소가 적용되고 다음 플레이어 행동에서 방어가 해제되는 회귀 테스트를 추가했다. Unity 컴파일러 3개 어셈블리 컴파일 성공, 에디터 외부 코어 테스트 191개 통과. 이번 확인에서 전투 방어 로직의 변경은 필요하지 않았다.


## 사용자 확정 몬스터 방어 추가 조건

현재 몬스터 메모리가 현재 플레이어 메모리보다 많을 때만 방어할 수 있다. 동률은 방어 불가다. 방어 비용 소모 전의 수치를 비교하며, 비용 소모 후 플레이어 이하가 되어도 이미 선택한 방어는 적용한다. 기존 AI 표의 방어 조건과 함께 만족해야 한다. 방어가 금지되면 공격을 재선택하고 비용이 부족하면 대기한다.

`BattleRules.CanMonsterDefend`에서 메모리 비교와 기존 각인/플레이어 과열 방어 금지를 공통으로 판단한다. 일반·속성·3기 AI와 `BattleSession.ValidateRequest`가 이 판단을 사용하므로 직접 요청으로도 조건을 우회할 수 없다. 사망한 플레이어는 비교에서 제외한다.

검증: 코어·테스트·게임 스크립트 컴파일 성공. 에디터 외부 코어 테스트 217개 통과(추가 조건 회귀 26개 포함). 동률/열세 요청 거부와 상태 보존, 투자 차감 전 비교, 일반·속성·3기 AI의 공격/대기 대체, 기존 금지 조건과 사망 플레이어 제외를 확인했다. PlayMode/데모 실행은 하지 않았다.

# 2026-10-05 시스템 수정

기준: `References/시스템 픽스 문서 (1).pdf`의 10-05 항목과 그 안에 연결된 [최신 전투 시스템 기획서](https://docs.google.com/document/d/1mxInwgEbY87ZiuaAHrdiOem1eM80JwjNWXajo8VmtRA/edit)의 기본 스킬 강화 절. 강화 횟수는 사용자 답변에 따라 승리한 전투만 누적한다.

## 적용

- 망각 강탈 등으로 같은 라운드에 메모리가 0이 돼도 다음 자신의 행동 시작에 고갈을 처리한다. 초기 메모리만큼 회복하고 그 행동 기회를 건너뛰며, 무료 방어·대기나 선제/연쇄 추가 행동으로 우회할 수 없다.
- 망각 기본 강탈을 5 → 10으로 변경한다. 대상 잔량과 행동자의 최대 공간에 맞춰 양쪽에 동일량을 적용한다.
- 각인 지연 피해를 최종 스킬 피해의 10% → 20%로 변경한다. 대상의 다음 행동 시작에 한 번 발생하며 방어 배율을 재적용하지 않는다.
- 잔상·각인·망각 기본 스킬은 1~3단계로 강화한다. 현재 5승 후 2단계 120, 10승 후 3단계 150이며 최대 3단계다. 새 플레이는 1단계 100으로 시작한다. 비용·폭주·치명타 등은 강화로 증가하지 않는다.
- 패배·무승부·중단은 누적하지 않는다. 승리 처리는 한 전투당 한 번이며 회복·테스트 조합 전환·같은 캐릭터의 씬 이동에는 누적을 유지한다. 전투가 끝난 뒤 해금한 단계는 다음 전투에 적용한다.
- TutorialDemo·MonsterAI_Test에 `BasicSkillEnhancement.asset`을 연결한다. Inspector에서 Victories Per Stage, 속성별 Stage Powers와 단계별 Animations/Effects를 수정할 수 있다. ID 대소문자와 공격력 3칸을 유지한다. 새 공개 API는 `SkillEnhancementRules`, `PlayerRuntimeState.VictoryCount/RecordBattleOutcome`, `SkillData.WithPower`다.
- 전투 스킬 버튼에 단계·위력을, 종료 안내에 승리 진행·강화를 표시한다. 제공된 강화 연출 자산이 없어 새 아트는 만들지 않았으며, Animations/Effects를 연결하면 해당 단계의 클립과 프리팹을 사용한다.

## 기획자 테스트 순서

1. Play를 끄고 `Data/Battle/BasicSkillEnhancement.asset`을 선택한다. 정식 기본값은 승리 주기 5, 각 스킬 공격력 100/120/150이다.
2. 빠른 강화 확인만 할 때 주기를 1로 임시 수정하고 Play를 새로 시작한다. MonsterAI_Test에서 한 전투를 이기면 2단계, 다음 승리 뒤 3단계를 해금한다. 다음 전투 버튼의 위력이 120/150인지 확인한다.
3. 패배 또는 전투 중단·초기화만 반복해도 누적이 오르지 않는지 확인한다. 승리 후 결과 화면에 머무르거나 초기화해도 승리 수가 중복 증가하지 않아야 한다.
4. 전투 기록의 기본 피해·최종 피해·비용을 비교한다. 강화 후 기본 공격력만 증가하고 비용·폭주 수치는 기존과 같아야 한다. 메모리 0은 다음 자기 행동에 고갈 결과가 기록돼야 한다.
5. Stop 후 승리 주기를 반드시 5로 되돌린다. Play 재시작은 새 게임이므로 승리 누적도 0부터 시작한다. 기존 10-04 Inspector 안내 PDF는 당시 기준이므로 최신 속성·강화 수치는 이 절을 따른다.

## 검증

Unity 6000.3.23f1의 컴파일러로 CK.Battle.Core, CK.Battle.Core.Tests, Assembly-CSharp 컴파일 성공. 에디터 외부 코어 테스트 261개 통과, 실패 0개(기존 217개와 고갈 6개·속성 20개·강화 18개). 기존 AI 표의 메모리 0 구간은 고갈을 끈 정책 테스트로 유지하고 실제 행동 불능·회복 흐름은 고갈 테스트에서 따로 확인했다.

두 씬의 강화 에셋·스크립트 GUID, 전투별 승리 집계 가드, 다음 전투의 공격력 재구성, 단계별 PlayableGraph·이펙트 정리와 Transform 포즈 복원 경로를 정적 확인했다. 연결한 Animator 클립은 Unity [AnimationClipPlayable](https://docs.unity3d.com/cn/6000.0/ScriptReference/Animations.AnimationClipPlayable.html)과 [수동 그래프 평가](https://docs.unity3d.com/ja/6000.0/ScriptReference/Playables.PlayableGraph.Evaluate.html)로 행동 시간에 맞춰 재생한다. 기존 UnityChan 코드의 중복 타입 경고는 남아 있다. 이번 세션에 Unity MCP가 제공되지 않아 Editor Console·실제 화면은 확인하지 못했으며, 게임·PlayMode·데모는 실행하지 않았다.

### 피해 표시 해석

일반/치명 피해는 명중했을 때의 계산 결과이며 실제 공격은 표시한 명중·치명 확률로 판정한다. 각인의 지연 피해는 즉시 공격 피해 숫자에 합산하지 않는다. 광역 스킬은 적별 피해의 최소~최대 범위를 표시하고 확률은 현재 선택한 대상을 기준으로 표시한다. 자원이 부족한 스킬은 메모리 또는 폭주 부족으로 표시한다. 예측은 난수와 실제 전투 상태를 소비하지 않는다.

## 2026-10-23 플레이어 망각 회복 예외 처리

확인 원본: `Docs/References/시스템 픽스 문서 (2).docx`. 이전 날짜의 항목은 기존 구현과 대조해 유지하고, 새 망각 회복 규칙을 공통 행동 계산에 반영했다.

- 플레이어의 망각 공격이 명중하면 대상 몬스터 메모리가 10 미만이어도 기본 회복량 10을 적용한다. 적이 8이면 적은 0이 되고 플레이어는 10을 회복한다. 사용자 확인에 따라 적이 이미 0이어도 10을 회복한다.
- 스킬·투자 비용을 먼저 차감한 뒤 회복하며 최대 메모리를 넘지 않는다. 예를 들어 메모리 100에서 비용 20을 지불하면 회복 후 90이 된다. 기본 회복량은 기존 `OblivionSteal` 설정값(10)을 사용한다.
- 빗나감 또는 속성 효과 비활성화에는 이 예외를 적용하지 않는다. 몬스터가 플레이어에게 쓰는 강탈과 일반 강탈은 기존 규칙을 유지한다. 이 절의 플레이어 망각 예외가 이전의 양측 동일량 이동 규칙보다 우선한다.
- 단일·광역 스킬 모두 공통 계산을 사용한다. 광역은 명중한 대상마다 회복을 계산하되 최대 메모리 공간을 공유하고 스킬·투자·폭주 비용은 한 번만 지불한다.
